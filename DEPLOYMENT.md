# Publish GuardianLink NG

## Before publishing

This is an academic prototype. Do not publish real victim records, locations, phone numbers, passwords, report evidence, or the local `securealert.db` file. The included `.gitignore` excludes those files.

## 1. Test locally

In the VS Code terminal:

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python app.py
```

Open `http://127.0.0.1:5000` and test registration, login, forgotten password, reporting, responder status updates, and the Safety Assistant.

## 2. Publish the code to GitHub

Create an empty GitHub repository named `guardianlink-ng`. In the VS Code terminal, inside this project folder, run:

```powershell
git init
git add .
git commit -m "Initial GuardianLink NG prototype"
git branch -M main
git remote add origin https://github.com/YOUR-USERNAME/guardianlink-ng.git
git push -u origin main
```

Replace `YOUR-USERNAME` with your GitHub username. GitHub may ask you to sign in. Never upload `.env`, the database, or real evidence files.

## 3. Deploy with Render

1. Create a Render account and connect GitHub.
2. Click **New** → **Blueprint**.
3. Select your `guardianlink-ng` repository. Render reads `render.yaml` and proposes a web service plus PostgreSQL database.
4. Create the resources and wait for the build to complete.
5. Open the public `onrender.com` URL provided by Render.

Before clicking **Apply**, enter these two environment-variable values in Render (choose your own private values):

- `BOOTSTRAP_ADMIN_EMAIL` — the email for your first admin account.
- `BOOTSTRAP_ADMIN_PASSWORD` — a strong password of at least 8 characters.

The app creates that admin account only if it does not already exist. After the first login, remove `BOOTSTRAP_ADMIN_PASSWORD` from Render and redeploy.

The deployment uses `gunicorn app:app` in production and `/health` as a health check. `SECRET_KEY` is generated by Render. Configure a real email provider before allowing real password-reset requests.

## Important production work before real users

- Replace demo passwords and prevent public signup for responder/admin accounts.
- Use database migrations rather than automatic table creation.
- Store uploaded evidence in private object storage, not the web server filesystem.
- Add CSRF protection, rate limiting, HTTPS-only cookies, audit logging, and a privacy notice.
- Obtain written approval before any connection to police, military, emergency, or security agencies.
